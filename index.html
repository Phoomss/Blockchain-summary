ปัญหาของ Centralized Technology

ระบบศูนย์กลางมีจุดอ่อน 4 ประการที่เป็นแรงผลักดันให้เกิด Blockchain

🔒

01 Security

ข้อมูลทั้งหมดรวมอยู่ที่ศูนย์กลาง เสี่ยงต่อการถูกโจมตีหรือขโมย

❌

02 Single Point of Failure

ถ้าเซิร์ฟเวอร์กลางล่ม ระบบทั้งหมดหยุดทำงานทันที

🕵

03 Data Privacy

ผู้ควบคุมศูนย์กลางสามารถเข้าถึงข้อมูลส่วนตัวของผู้ใช้ได้

👁

04 Transparency

ผู้ใช้ทั่วไปไม่สามารถตรวจสอบหรือยืนยันข้อมูลได้โดยตรง

เทคโนโลยีที่อยู่เบื้องหลัง Blockchain

Blockchain ประกอบด้วย 3 เทคโนโลยีหลัก

🌐

01 Peer-to-Peer Network

ทุก Node เชื่อมต่อกันโดยตรง ไม่มีเซิร์ฟเวอร์กลาง แต่ละ Peer รับ-ส่งข้อมูลได้เท่าเทียมกัน

📜

02 Distributed Ledger Technology

บันทึกธุรกรรมออนไลน์ที่จัดเก็บข้อมูลพร้อมกันในหลายที่ในเวลาเดียวกัน

🔐

03 Cryptography

เทคนิคการเข้ารหัสข้อมูลเพื่อปกป้องความเป็นส่วนตัวและความสมบูรณ์ของข้อมูล

Centralized vs Decentralized vs Distributed

🏢

Centralized

ควบคุมโดยจุดศูนย์กลางเดียว ถ้าล่มระบบทั้งหมดพัง

🕸

Decentralized

กระจายการควบคุมออกไปหลายจุด แต่ยังมีลำดับชั้นบ้าง

⚡

Distributed

กระจายทั้งข้อมูลและการประมวลผลทุก Node อย่างสมบูรณ์

Distributed Ledger Technology (DLT)

DLT คือการบันทึกข้อมูลแบบออนไลน์ที่จัดเก็บไว้หลายที่พร้อมกัน

🔀

Decentralization

กระจายข้อมูลไปหลายโหนด ไม่มีจุดควบคุมกลาง

🤝

Consensus

ทุก Node ต้องตกลงยืนยันธุรกรรมก่อนจึงจะบันทึกได้

🔎

Transparency

ทุกคนสามารถตรวจสอบธุรกรรมได้

🛡

Security

ข้อมูลถูกป้องกันด้วยการเข้ารหัส

Blockchain คือ ระบบการเก็บข้อมูลแบบกระจาย (แบบหนึ่งของ DLT) ที่มีความน่าเชื่อถือ โปร่งใส และ ไม่ต้องอาศัยคนกลาง — ข้อมูลที่บันทึกใน Blockchain ไม่สามารถเปลี่ยนแปลงหรือแก้ไขได้ (Immutability)

ส่วนที่ 4

Cryptography (การเข้ารหัส)

เทคนิคการเข้ารหัสที่ใช้ใน Blockchain มี 2 ประเภทหลัก

🗹

1) Public-Key Cryptography (Asymmetric)

ใช้กุญแจคู่:

  • Public Key — แจกได้ทั่วไป ใช้สำหรับเข้ารหัส
  • Private Key — เก็บเป็นความลับ ใช้สำหรับถอดรหัส
เปรียบได้กับกล่องล็อกที่ทุกคนหยอดจดหมายได้ (Public Key) แต่มีแค่เจ้าของที่เปิดได้ (Private Key)
🔗

2) Hash Function

รับข้อมูลอะไรก็ได้และสร้าง output เป็นสตริงความยาวคงที่

  • ไม่ว่า input จะมีขนาดเท่าไร output จะมีขนาดเท่ากันเสมอ
  • One-way function — ไม่สามารถย้อนกลับข้อมูลเดิมได้
  • เปลี่ยน input แม้ 1 ตัว → hash เปลี่ยนหมด
ตัวอย่าง: SHA-256 (ใช้ใน Bitcoin)

Symmetric vs Asymmetric Encryption

คุณสมบัติSymmetricAsymmetric
จำนวนกุญแจ1 กุญแจ (ใช้ร่วมกัน)2 กุญแจ (Public + Private)
ความเร็วเร็วช้ากว่า
ความปลอดภัยต้องแชร์กุญแจ เสี่ยงถูกดักฟังปลอดภัยกว่า
ตัวอย่างAES, DESRSA, ECC (ใช้ใน Blockchain)

🏢 Workshop: EasyBank Smart Contract

ฝึกเขียน Smart Contract ธนาคารอย่างง่ายที่มีฟังก์ชัน 3 อย่าง

💰

getBalance()

ดูยอดเงินคงเหลือของตัวเอง เป็น public view ไม่เสีย Gas

📥

deposit()

ฝากเงินเข้าบัญชี รับ ETH ได้ด้วย payable แล้วเพิ่มยอดใน mapping

📤

withdraw(uint256)

ถอนเงิน ตรวจสอบว่ามีเงินพอ แล้วโอนกลับไปยังผู้ถอน

📝 โค้ด EasyBank.sol (ตัวอย่างสมบูรณ์)

// SPDX-License-Identifier: MIT pragma solidity ^0.8.0; contract EasyBank { // 1) ประกาศตัวแปร mapping address → ยอดเงิน mapping(address => uint256) balances; // 2) getBalance: ดูยอดเงินของตัวเอง (ไม่เปลี่ยน state) function getBalance() public view returns (uint256) { return balances[msg.sender]; } // 3) deposit: ฝากเงิน (รับ ETH ได้ด้วย payable) function deposit() public payable { balances[msg.sender] += msg.value; } // 4) withdraw: ถอนเงิน function withdraw(uint256 amount) public { // ตรวจสอบว่ามีเงินพอถอน require(balances[msg.sender] >= amount, "Insufficient balance"); // ลดยอดเงินก่อน (ป้องกัน reentrancy attack) balances[msg.sender] -= amount; // โอนเงินกลับไปที่ผู้ถอน (bool success, ) = msg.sender.call{value: amount}(""); require(success, "Withdraw failed!!"); } }

₿ Bitcoin และ Blockchain 1.0

Bitcoin คือระบบเงินดิจิทัลแบบ Peer-to-Peer ที่เปิดตัวปี 2009 บน Blockchain — ไม่ต้องมีธนาคารกลาง

📈

UTXO Model

Bitcoin ใช้ Unspent Transaction Output (UTXO) แทนยอดคงเหลือแบบบัญชี

  • เปรียบเหมือนการหยิบธนบัตรมาจ่ายแล้วรับเงินทอน
  • Input = UTXO ที่เป็นของผู้ส่ง
  • Output = UTXO ใหม่ให้ผู้รับ + เงินทอนกลับผู้ส่ง
ต่างจาก Ethereum ที่ใช้ Account-based Model (ยอดเงินในบัญชี)
🔨

Proof of Work & Mining

Proof of Work (PoW) ให้ Miner แข่งกันค้นหาค่า nonce ที่ทำให้ hash ผ่าน difficulty

  • ผู้สำเร็จเสนอ Block ใหม่และรับ Block Reward
  • ทำให้การแก้ประวัติย้อนหลังต้องใช้พลังประมวลผลสูงมาก
  • Bitcoin ใช้ SHA-256 ในกระบวนการ Mining

♦ Ethereum, EVM, ABI & Gas

Ethereum คือ Blockchain ที่ออกแบบให้รัน Smart Contract และ dApp ได้อย่างสมบูรณ์

💰

ETH, Wei & Gwei

Gwei1 Gwei = 109 Weiแสดง Gas Price

⚙

EVM (Ethereum Virtual Machine)

สภาพแวดล้อมเสมือนที่โหนด Ethereum ใช้ประมวลผล Smart Contract ให้ได้ผลลัพธ์ตามกฎเดียวกัน

  • รัน EVM Bytecode ไม่ใช่ Solidity source code โดยตรง
  • ทุกโหนดรันโค้ดเดียวกันและได้ผลเหมือนกัน
📜

ABI (Application Binary Interface)

คำอธิบาย interface ของ contract เช่น function, parameter, return type, event เพื่อให้โปรแกรมภายนอกสื่อสารกับ contract ได้

  • Remix, Web3.js, ethers.js ต้องใช้ ABI
  • สร้างอัตโนมัติตอน compile Solidity

🔄 Solidity → EVM Bytecode Flow

1

Solidity Source Code (.sol)

เขียนด้วยภาษา Solidity ที่มนุษย์อ่านได้

2

Solidity Compiler (solc / Remix)

แปลง source code เป็น EVM Bytecode + ABI

3

Deploy Bytecode → Contract Address

Bytecode ถูก deploy สร้าง Contract Address บนเครือข่าย

4

Web/Remix/dApp ใช้ ABI เรียก Function

ผู้ใช้ interact ผ่าน ABI โดยไม่ต้องรู้ Bytecode

💉

Gas คืออะไร?

Gas คือหน่วยวัดปริมาณงานคำนวณที่ EVM ต้องทำ

Transaction Fee = Gas Used × Gas Price

  • เขียนข้อมูลลง Blockchain ใช้ Gas มากกว่าการอ่าน
  • Code ที่ซับซ้อนหรือเขียน Storage มากใช้ Gas มากขึ้น
  • ผู้ส่ง Transaction จ่าย Gas เป็น ETH

💰 ERC Token Standards: ERC-20 / ERC-721 / ERC-1155

ERC (Ethereum Request for Comments) คือมาตรฐาน interface ของ Smart Contract บน Ethereum สำหรับ Token

💰

ERC-20 — Fungible Token

Token แต่ละหน่วย ทดแทนกันได้ เช่น 1 Token A = 1 Token A

Functions หลัก:

  • totalSupply() — จำนวน Token ทั้งหมด
  • balanceOf(address) — ยอด Token ของ address
  • transfer(to, amount) — โอน Token
  • approve(spender, amount) — อนุญาต spender
  • transferFrom(from, to, amount) — โอนตาม allowance
☞ เหรียญ, utility token, governance token, คะแนน
🎨

ERC-721 — Non-Fungible Token

แต่ละ Token มี tokenId เฉพาะ และมีเจ้าของชัดเจน — ทดแทนกันไม่ได้

Functions หลัก:

  • ownerOf(tokenId) — เจ้าของ Token ID นั้น
  • balanceOf(owner) — นับ NFT ที่ owner ถือ
  • safeTransferFrom(...) — โอน NFT อย่างปลอดภัย
  • tokenURI(tokenId) — ชี้ไปยัง Metadata
☞ งานศิลป์, ของสะสม, ใบรับรอง
🎮

ERC-1155 — Multi Token Standard

Contract เดียวรองรับ Token หลายชนิด แต่ละ tokenId มีจำนวนมากกว่า 1 ได้

  • Fungible, Non-Fungible, Semi-Fungible ในที่เดียว
  • รองรับ Batch Transfer ช่วยลดจำนวน Transaction
  • ตัวอย่าง: _mint(msg.sender, 1, 10, "") = mint tokenId=1 จำนวน 10 หน่วย
☞ เกม, ไอเทมหลายชนิด, Gold Coin, Sword, Ticket ใน contract เดียว

📝 แนวข้อเขียนสำหรับสอบกลางภาค

16 ข้อที่ควรตอบได้ — พร้อมแนวคำตอบสำหรับใช้ตอบในห้องสอบ

❓ ข้อ 1: Blockchain คืออะไร และหลักการทำงานเป็นอย่างไร?

Blockchain คือระบบบันทึกข้อมูลแบบกระจาย (DLT) โดยข้อมูลธุรกรรมถูกกระจายไปยังหลายโหนดในเครือข่าย P2P ใช้ cryptography ยืนยันตัวตนและตรวจสอบข้อมูล จากนั้นใช้ consensus ให้โหนดเห็นพ้องกัน ธุรกรรมที่ยืนยันแล้วถูกบันทึกเป็น block เชื่อมกับ block ก่อนหน้าด้วย hash ทำให้การแก้ข้อมูลย้อนหลังทำได้ยากมาก

❓ ข้อ 2: DLT กับ Blockchain ต่างกันอย่างไร?

DLT เป็นแนวคิดกว้างของสมุดบัญชีแบบกระจายที่มีข้อมูลสำเนาหลายจุดและอัปเดตร่วมกัน ส่วน Blockchain เป็น DLT ชนิดหนึ่งที่จัดข้อมูลเป็นบล็อกและเชื่อมบล็อกต่อกันเป็นลำดับ ดังนั้น Blockchain ทุกระบบเป็น DLT แต่ DLT บางระบบอาจไม่ได้จัดข้อมูลเป็น chain of blocks

❓ ข้อ 3: Cryptography และ Hash มีบทบาทต่อ Blockchain อย่างไร?

Public-key cryptography ให้ผู้ใช้ใช้ private key ลงนามธุรกรรมพิสูจน์สิทธิ์ ส่วน hash function รับข้อมูลแล้วสร้างค่าความยาวคงที่แบบ one-way ใช้ตรวจ integrity และเชื่อม block หากข้อมูลเดิมถูกแก้ hash จะเปลี่ยน ทำให้เครือข่ายตรวจพบความผิดปกติได้

❓ ข้อ 4: Bitcoin คืออะไร และทำงานอย่างไร?

Bitcoin คือระบบเงินดิจิทัล P2P ที่ใช้ Blockchain บันทึกการโอน BTC ผู้ส่งใช้ private key ลงนาม broadcast ไปยังเครือข่าย โหนดตรวจสอบกฎ จากนั้น miner ใช้ Proof of Work สร้าง block ใหม่ Bitcoin ใช้โมเดล UTXO และมี block reward ที่ลดลงตาม halving

❓ ข้อ 5: Bitcoin Halving คืออะไร และมีเหตุผลอะไร?

Bitcoin Halving คือการลด block reward ลงครึ่งหนึ่งทุก 210,000 blocks (~4 ปี) มีวัตถุประสงค์เพื่อควบคุมอัตราการออก BTC ใหม่ ทำให้อุปทานเพิ่มช้าลง และรักษาข้อจำกัดอุปทานสูงสุดประมาณ 21 ล้าน BTC

❓ ข้อ 6: Wallet คืออะไร? Password, Private Key และ SRP ต่างกันอย่างไร?

Password ปลดล็อกข้อมูล wallet ในอุปกรณ์  |  Private Key ควบคุมและเซ็นธุรกรรมของ account หนึ่ง  |  Secret Recovery Phrase (12 คำ) เป็นข้อมูลรากที่ใช้กู้ wallet และ derive private keys หลายบัญชี — SRP และ private key ต้องเก็บเป็นความลับสูงสุด

❓ ข้อ 7: MetaMask, Sepolia และ SepoliaETH คืออะไร?

MetaMask คือ self-custody wallet ที่ผู้ใช้ถือกุญแจเอง เชื่อม Ethereum/EVM รวมถึง Remix/dApp  |  Sepolia คือ Ethereum Testnet ทดลองก่อนขึ้น Mainnet  |  SepoliaETH คือ ETH ทดสอบสำหรับจ่าย Gas บน Sepolia ไม่มีมูลค่าจริง รับได้จาก faucet

❓ ข้อ 8: Smart Contract คืออะไร? ขั้นตอนตั้งแต่เขียนจนใช้งาน?

Smart Contract คือโปรแกรมที่ deploy บน Blockchain ทำงานตาม logic อัตโนมัติ ขั้นตอน: เขียน Solidity → compile ได้ Bytecode + ABI → deploy สร้าง Contract Address → Call เพื่ออ่าน (ฟรี) หรือ Send Transaction เพื่อแก้ state (เสีย Gas)

❓ ข้อ 9: EVM, Bytecode และ ABI คืออะไร?

EVM คือสภาพแวดล้อมเสมือนที่โหนด Ethereum ใช้รัน Smart Contract ให้ได้ผลเหมือนกัน  |  Bytecode คือรหัสที่ compiler สร้างจาก Solidity ให้ EVM รัน  |  ABI คือคำอธิบาย interface ของ contract เพื่อให้ Remix, Web3.js, dApp เรียกใช้ได้

❓ ข้อ 11: อธิบาย msg.sender, msg.value, view, payable และ modifier

msg.sender = address ผู้เรียก function  |  msg.value = Wei ที่ส่งมากับ transaction  |  view = อ่าน state ได้แต่ห้ามแก้  |  payable = รับ ETH ได้  |  modifier = กำหนดเงื่อนไข/พฤติกรรมของ function เช่น onlyOwner

❓ ข้อ 12: ERC-20 คืออะไร?

ERC-20 เป็นมาตรฐาน Fungible Token บน Ethereum — Token แต่ละหน่วยทดแทนกันได้ มาตรฐานกำหนด interface สำคัญ: totalSupply, balanceOf, transfer, approve, allowance, transferFrom ทำให้ wallet, exchange และ dApp รองรับ Token ต่าง ๆ ด้วยวิธีเดียวกัน

❓ ข้อ 13: ERC-721 กับ ERC-1155 ต่างกันอย่างไร?

ERC-721 เน้น NFT ที่แต่ละ tokenId เป็นรายการเฉพาะมีเจ้าของหนึ่งชุด เหมาะของสะสม/งานศิลป์  |  ERC-1155 เป็น multi-token standard ที่ contract เดียวมี tokenId หลายชนิด แต่ละ ID มีจำนวนหลายหน่วยได้ รองรับ batch transfer เหมาะกับเกม

❓ ข้อ 14: NFT คืออะไร และรูปภาพอยู่บน Blockchain หรือไม่?

NFT คือ Non-Fungible Token ที่ใช้แทนสิทธิ์หรือรายการที่มีเอกลักษณ์ ตัว Token บน Blockchain มักเก็บ tokenId, owner และ URI ส่วนรูปภาพและรายละเอียดมักเก็บใน metadata ภายนอก เช่น IPFS หรือ Web URL — NFT ≠ รูปภาพเก็บ on-chain เสมอไป

❓ ข้อ 15: ขั้นตอนสร้าง NFT แบบ ERC-1155

สร้าง ERC-1155 contract ใน Remix/OpenZeppelin → เตรียมรูปและ metadata JSON → ใช้ URL ของ metadata เป็น URI → mint: _mint(msg.sender, 1, 10, "") → compile + เชื่อม MetaMask → deploy บน Sepolia จ่าย Gas ด้วย SepoliaETH → verify source code บน Sepolia Etherscan → import NFT เข้า wallet

❓ ข้อ 16: Gas คืออะไร และเกี่ยวข้องกับ Smart Contract อย่างไร?

Gas คือหน่วยวัดงานคำนวณที่ EVM ต้องทำ การ deploy contract, แก้ state, mint หรือ transfer ต้องใช้ Gas ผู้ส่ง transaction จ่ายเป็น ETH  |  Transaction Fee = Gas Used × Gas Price  |  code ที่ซับซ้อนหรือเขียน storage มากใช้ Gas มากขึ้น
