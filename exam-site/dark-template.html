ส่วนที่ 11

💰 ERC Token Standards: ERC-20 / ERC-721 / ERC-1155

ERC (Ethereum Request for Comments) คือมาตรฐาน interface ของ Smart Contract บน Ethereum สำหรับ Token

💰

ERC-20 — Fungible Token

Token แต่ละหน่วย ทดแทนกันได้ เช่น 1 Token A = 1 Token A

Functions หลัก:

  • totalSupply() — จำนวน Token ทั้งหมด
  • balanceOf(address) — ยอด Token ของ address
  • transfer(to, amount) — โอน Token
  • approve(spender, amount) — อนุญาต spender
  • transferFrom(from, to, amount) — โอนตาม allowance
☞ เหรียญ, utility token, governance token, คะแนน
🎨

ERC-721 — Non-Fungible Token

แต่ละ Token มี tokenId เฉพาะ และมีเจ้าของชัดเจน — ทดแทนกันไม่ได้

Functions หลัก:

  • ownerOf(tokenId) — เจ้าของ Token ID นั้น
  • balanceOf(owner) — นับ NFT ที่ owner ถือ
  • safeTransferFrom(...) — โอน NFT อย่างปลอดภัย
  • tokenURI(tokenId) — ชี้ไปยัง Metadata
☞ งานศิลป์, ของสะสม, ใบรับรอง
🎮

ERC-1155 — Multi Token Standard

Contract เดียวรองรับ Token หลายชนิด แต่ละ tokenId มีจำนวนมากกว่า 1 ได้

  • Fungible, Non-Fungible, Semi-Fungible ในที่เดียว
  • รองรับ Batch Transfer ช่วยลดจำนวน Transaction
  • ตัวอย่าง: _mint(msg.sender, 1, 10, "") = mint tokenId=1 จำนวน 10 หน่วย
☞ เกม, ไอเทมหลายชนิด, Gold Coin, Sword, Ticket ใน contract เดียว

📊 ตารางเปรียบเทียบ ERC

หัวข้อ ERC-20 ERC-721 ERC-1155
ประเภท Fungible Non-Fungible Multi-token
แต่ละหน่วยเหมือนกัน? ✅ ใช่ ❌ ไม่ใช่ ขึ้นกับ tokenId
Token ID ไม่เน้น tokenId รายชิ้น ทุก NFT มี tokenId ทุกชนิดใช้ tokenId
จำนวนต่อ ID ยอดรวมทั้งหมด ปกติ 1 เจ้าของต่อ tokenId 1 หรือหลายหน่วยต่อ tokenId
Batch Transfer — — ✅ รองรับ
เหมาะกับ เหรียญ/คะแนน งานศิลป์/ของสะสม เกม/ไอเทมจำนวนมาก

💡 Mnemonic จำง่าย: 20 = Money (เหรียญเหมือนกัน)  |  721 = One-by-one NFT (แต่ละ tokenId เฉพาะ)  |  1155 = Many-in-one (หลายชนิดใน contract เดียว)

ส่วนที่ 12

🎨 NFT และ Metadata

NFT (Non-Fungible Token) คือ Token ที่ใช้แทนสิทธิ์หรือรายการดิจิทัลที่มีเอกลักษณ์เฉพาะ

🚫 จุดที่มักเข้าใจผิด: NFT ไม่จำเป็นต้องเป็น "รูปภาพที่เก็บอยู่บน Blockchain" — ตัว Token บนเชนมักเก็บเพียง tokenId, owner และ URI ส่วนรูป, ชื่อ, description มักอยู่ใน metadata ภายนอก เช่น IPFS หรือ Web Server

📄

Metadata JSON

Metadata อยู่ในรูป JSON ที่ Smart Contract ใช้ URI ชี้ไป

{ "name": "MaiyNFT", "description": "My first NFT", "image": "https://.../image.png" }
📷

On-chain vs Off-chain Metadata

แบบ ข้อดี ข้อควรระวัง
On-chain คงอยู่ตาม Blockchain ใช้ Gas/Storage สูง
IPFS ลดค่าใช้จ่าย เก็บไฟล์ใหญ่ได้ ต้องดูแล URI และ pin ข้อมูล
Web/GitHub ทำง่าย เหมาะทดลอง เจ้าของอาจแก้/ลบไฟล์ได้

🚀 Workflow สร้าง NFT (ERC-1155) จากใบงาน

1

สร้าง ERC-1155 Contract ใน Remix / OpenZeppelin

ใช้ OpenZeppelin เป็น Base เพื่อความปลอดภัย

2

เตรียมรูป NFT และ Metadata JSON ใน GitHub

ใช้ Raw URL ของรูปใน JSON และ Raw URL ของ JSON เป็น URI

3

Mint Token

_mint(msg.sender, 1, 10, "") = mint tokenId=1 จำนวน 10 หน่วย

4

Compile & Deploy บน Sepolia ผ่าน MetaMask

ยืนยัน Transaction จ่าย Gas ด้วย SepoliaETH

5

Verify Source Code บน Sepolia Etherscan

ช่วยให้ผู้ใช้ตรวจสอบว่า source code ตรงกับ bytecode ที่ deploy ไว้

6

Import NFT & ทดสอบส่งไปยัง Wallet อื่น

ตรวจสอบผ่าน MetaMask และ Sepolia Etherscan
